# V2 从这里开始

这不是旧工程的“功能加长版”。`v2/` 是一套按工业视觉常规流程重新建立的学习与开发工程；旧版只保留为 Legacy 对照。

## 先记住三个结论

1. 现在没有真实的 PCB 下视相机、针排上视相机、运动轴反馈和安全互锁，所以离线结果只能是 `EngineeringOnly`，并且 `MotionAllowed=false`。
2. `0.05 mm` 不能由程序显示四位小数来证明。它最终必须由真实光学、独立量具、运动闭环、GR&R、温漂和长期样本共同验收。
3. Shape Model 只做粗定位。正式测量必须继续做跟随 ROI、亚像素孔/针尖定位、编号对应、N 点刚体拟合、逐针残差和 T 轴旋转中心换算。

## 三类能力不要混在一起

| 主题 | 已真实实现（当前软件） | 教学/离线演示 | 待硬件/量产 |
|---|---|---|---|
| 运行服务 | 本机 Socket、状态机、单消费者、请求幂等、File 图像检测、原图/结果保存 | 9201 工程端口运行合成图片 | 真实相机、PLC、轴反馈、断电恢复和生产网络安全 |
| 视觉算法 | C# 调用 HALCON 完成质量门禁、Blob、亚像素圆、坐标变换、点列配准 | HDevelop 01～09；圆形合成孔和针尖 | 真实产品边缘模型、光学鲁棒性、误差真值与节拍 |
| WPF | 10 个 Feature 的模块化外壳；生产页可触发离线 Runtime | ROI、模板、标定、配方、回归、追溯大部分为内存教学数据 | 真图 Viewer、配方持久化、模型创建、标定向导、审批发布 |
| 配方完整性 | SHA-256 验证组件及单元测试 | 当前离线配方是普通 JSON | 发布包目录、活动索引、审批签名、标定包和 Runtime 激活/回滚 |
| 设备能力 | XYT 数学与运动禁止门有测试 | 合成仿射与理想残差 | 光学选型、真实标定、PLC 安全、`0.05 mm`、GR&R 和插针验收 |

这里的“已真实实现”只说明软件代码确实执行，不说明真实设备能力已经得到证明。

## 你应该按什么顺序学

不要从 Socket 或按钮开始。建议严格按下面顺序：

1. 阅读 [常规视觉项目开发流程](02-常规视觉项目开发流程.md)，理解项目为什么按阶段推进。
2. 阅读 [光学选型与误差预算](03-光学选型与误差预算.md)，先理解为什么只有“工作距离 200 mm”不能选出相机。
3. 在 HDevelop 依次运行 `v2/hdevelop/01...09`，逐个观察算子和中间结果。
4. 阅读 [坐标系、标定与 XYT 原理](04-坐标系标定与XYT原理.md)，重点理解九点标定、T 轴中心和点列配准的区别。
5. 双击 `v2/scripts/01_verify_v2.cmd`，确认源码、HALCON Runtime 和离线测试链能运行。
6. 双击 `v2/scripts/02_start_runtime.cmd`，启动 C# 视觉服务。
7. 双击 `v2/scripts/03_trigger_offline_once.cmd`，通过 Socket 触发一次离线检测。
8. 双击 `v2/scripts/04_start_engineering_ui.cmd`，在 WPF 中按“项目开发向导”学习 ROI、模板、标定、配方和回归。
9. 有真实硬件后，再执行 [设备调试与量产导入 SOP](10-设备调试与量产导入SOP.md)。

```text

├─ src/
│  ├─ Vision.Contracts/          Socket/工程端 DTO，不含 HALCON 类型
│  ├─ Vision.Domain/             坐标、结果语义、失败码、配方规则
│  ├─ Vision.Application/        检测用例、状态机、点列配准
│  ├─ Vision.Halcon/             HALCON File读图、质量、定位和合成平面映射
│  ├─ Vision.Infrastructure/     哈希校验组件、结果和事件保存
│  ├─ Vision.Runtime/            离线服务与生产/工程两个Socket端点（生产检测禁用）
│  ├─ Vision.Engineering.Wpf/    模块化工程站外壳与教学页面
│  └─ Vision.Trigger.Client/     最小上位机 Socket 示例
├─ tests/                        分层自动测试
├─ hdevelop/                     01～09 的 HALCON 学习原型
├─ datasets/                     三例合成数据、清单和合成标定文件
├─ config/                       当前Runtime直接读取的离线配方
```

当前磁盘中没有 `v2/packages/` 发布包目录。`Vision.Infrastructure` 内的哈希验证器和活动索引仓储是经过单元测试的基础组件，但 `Vision.Runtime` 目前没有装配它们，而是直接读取 `config/recipes/*.json`；所以不能把“存在配方包类”理解成发布、审批、激活和回滚已经完成。

## `.hdev`、`.hdvp`、C# 和 EXE 到底是什么关系

- `.hdev`：HDevelop 主程序，像实验入口或 C# 的 `Program.cs`，适合逐行执行、看变量和中间图。
- `.hdvp`：HDevelop 外部过程，概念上更像一个可复用方法，不是一个 C# 类，也不是 DLL。
- `HOperatorSet`：C# 对 HALCON 算子的直接封装；本 V2 的正式运行算法采用这种方式。
- `halcondotnet.dll + HALCON Runtime`：C# 程序运行 HALCON 算子所需的托管接口和原生运行库。
- `Vision.Runtime.exe`：由 .NET 生成的最终服务。HALCON 本身不是用来把 HDevelop 项目直接编译成通用 Windows EXE 的 IDE。

本工程选择的产品化技术路线是：

```text
HDevelop 原型与学习
        ↓ 算法冻结后移植/实现
C# Vision.Halcon（HOperatorSet）
        ↓
Vision.Application 编排
        ↓
Vision.Runtime.exe + HALCON Runtime
```

WPF 工程站是独立工程工具，不是算法 DLL，也不是当前生产 Runtime 的必要组成。现在它只有离线生产页接入 Runtime，其余工程编辑流程仍需继续开发。

## 当前能证明什么，不能证明什么

当前离线版本能证明：

- 项目分层和依赖方向正确；
- HALCON 图像能进入 C# 阶段化流水线；
- 孔/针点具有编号，补偿来自刚体配准而不是姿态直接相减；
- T 轴中心公式、状态机、失败码、内存幂等、离线图像归档和结果映射有自动测试；
- 三例合成数据可复现，Disposition 和 FailureCode 可回归。

当前不能证明：

- 相机、镜头、光源已经选对；
- 钢针反光、PCB 翘曲、批次变化下仍稳定；
- 真实相机标定达到要求；
- WPF 中画出的 ROI 已写入并驱动生产算法；
- Shape Model 已由真实样本创建、验证并发布；
- 配方哈希包已经由 Runtime 激活，或审批/回滚流程已经完成；
- 当前三例数据集具有位置真值、统计覆盖或真实缺陷代表性；
- 运动执行后每根针到每个孔的误差小于 0.05 mm；
- 设备可以安全插入。

这些限制不是“项目没写完”的借口，而是工业视觉必须诚实保留的验收门。它们在 [量产就绪矩阵](12-量产就绪矩阵.md) 中逐项列出，只有取得实机证据后才能关闭。
