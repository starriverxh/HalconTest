# 系统架构与模块边界

## 为什么要重新分层

旧版把采图、HALCON、补偿、Socket、文件和 UI 逐步堆进少数几个大类。初期容易看到结果，后期却无法回答：错误来自图像、算法、标定、运动还是通信？V2 用依赖方向把这些问题隔开。

```text
Vision.Domain                       纯业务与数学，不依赖外部框架
      ↑
Vision.Application                  检测用例和状态机
      ↑                 ↑
Vision.Halcon          Vision.Infrastructure
      ↑                 ↑
      └──── Vision.Runtime ──── Vision.Contracts ──── 上位机/PLC客户端

Vision.Engineering.Wpf ─────────── Vision.Contracts/展示模型
```

约束：

- `HObject`、`HTuple` 和 HALCON 模型句柄只能存在于 `Vision.Halcon` 内。
- Domain 不认识 WPF、Socket、JSON 路径和相机厂商 SDK。
- WPF 不直接执行生产 HALCON 算子；它通过工程用例/服务获得结果。
- 生产端点不允许客户端提交任意本地图片路径；离线图片只允许从回环地址工程端点进入。
- 所有运动许可只在 Application/Runtime 的受控决策处产生，UI 不能自己把结果改成可运动。

## 目标量产版的一次检测数据流

下面是本项目采用的**设计基准**，用于告诉你常规视觉工位最终应走到哪里；它不表示离线 V2 已经拥有真实相机、轴反馈和全部发布功能。

```text
触发 requestId
  ↓
协议版本、字段、状态和幂等检查
  ↓
锁定本周期配方/标定快照
  ↓
安全互锁与轴静止检查
  ↓
PCB相机采集 + 元数据/轴反馈
  ↓
图像质量 → PCB粗定位 → 跟随ROI → 孔精定位 → 机器坐标
  ↓
针排相机采集 + 元数据/轴反馈
  ↓
图像质量 → 针排粗定位 → 针尖精定位 → 缺针/弯针/针距 → 机器坐标
  ↓
按 P1...PN 编号对应 → 刚体拟合 → 逐针残差
  ↓
T轴旋转中心和运动顺序换算 → 安全范围/不确定度门禁
  ↓
保存原图、叠加图、测量值、版本快照、状态历史
  ↓
返回 Disposition + MeasurementValid + MotionAllowed + XYT
```

当前 V2 真正跑通的是：工程端 Socket → 文件双图 → 图像质量 → Blob 粗定位 → XLD 圆拟合 → 平面仿射映射 → P1…PN 刚体配准 → 逐针残差 → 原图/JSON/事件归档。Shape Model 代码分支存在，但默认配方没有正式 `.shm` 工件；畸变校正、真实帧 ID/轴快照、叠加图、不可变配方包和硬件指纹门禁仍属于后续实机工程。离线图源会强制得到 `MotionAllowed=false`。

## 四个不能混在一起的结果语义

| 字段 | 回答的问题 | 示例 |
|---|---|---|
| SystemHealth | 服务、相机、标定、存储是否健康 | 相机超时属于系统故障 |
| MeasurementValid | 是否得到可信、完整的几何测量 | 找不到 PCB 属于测量无效 |
| ProductResult | 产品本身是否合格 | 缺针、弯针属于产品 NG |
| MotionAllowed | 这一次补偿是否允许设备执行 | 离线模拟永远为 false |

`Product NG` 是一次正常结束的检测，不应该把整个工位打进 `Faulted`。相机掉线、配方损坏、标定失效或写盘失败才是系统故障。

## 为什么是单消费者队列

相机句柄、HALCON 模型句柄、活动配方和设备轴属于独占资源。运行服务使用有界单消费者队列，确保同一时刻只有一个检测周期操作这些资源。它还带来三个好处：

1. 同一个 `requestId` 重发时返回原来的 Task/结果，不会再次拍照；
2. 不会因为两个 Socket 客户端同时触发而交叉使用图像和轴反馈；
3. HALCON 超时后不会立刻由第二条线程同时释放或重用同一批原生对象。

## 生产端点和工程端点

| 端点 | 默认地址 | 用途 | 是否接收图片路径 |
|---|---|---|---|
| Production | `127.0.0.1:9200` | PLC/上位机正式触发 | 否 |
| Engineering | `127.0.0.1:9201` | 离线学习和本地图像回放 | 是，仅回环地址 |

没有双相机和安全握手时，Production 返回 `STATION_UNCOMMISSIONED`。Engineering 可以跑完整离线链，但结果必须为 `EngineeringOnly` 且 `MotionAllowed=false`。

## 配方与标定为什么分开

- 产品配方描述“这个产品应该怎么看”：ROI、模板、名义点、阈值、判定公差。
- 工位标定描述“这台设备如何把图像换成机械坐标”：相机、镜头、工作平面、T轴中心、工具偏置。

同一个 PCB 配方可以在多台设备使用，但每台设备应拥有自己的标定包。目标量产实现应在周期开始时把两者组合成不可变快照，并把配方哈希、标定哈希、相机序列号和算法版本写入每个结果。

当前离线 Runtime 仍从普通 JSON 配方仓库加载产品配方，两个平面标定文件由算法阶段按路径读取；仓库里虽然有哈希包校验类及测试，但尚未接入正式 Runtime 装配。因此不得把当前代码误认为已经完成“周期快照锁定”和“签名发布”。

## V1 和 V2 的边界

- 根目录旧 `src/`、`halcon/` 和旧解决方案：V1/S1 离线概念样机，只用于对照。
- `v2/`：新架构和后续真实设备开发入口。
- V2 不读取 V1 的运行结果、模板或标定文件作为生产依据。
- 可以复制旧算法思想到 V2，但必须经过 V2 的阶段接口、失败码、数据集回归和版本门禁。
