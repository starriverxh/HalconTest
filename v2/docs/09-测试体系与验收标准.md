# 测试体系与验收标准

## 为什么“测试通过”仍可能不是视觉合格

测试分为软件正确性、离线算法能力、硬件链和最终工艺能力。当前 `01_verify_v2.cmd` 执行
**52 项 Domain/Application/Architecture/Runtime/Infrastructure/WPF 自测**，外加 HALCON C# Smoke、
3 组锁定合成数据回归和 9 个 HDevelop 执行检查；这些通过只能证明对应代码路径，不能等同于真实插针成功。

当前各 `.Tests` 项目是可执行的控制台自测程序集，不是 xUnit/NUnit 测试项目：任一断言失败会返回非零退出码，
由 CMD 01 立即停止。这样便于当前离线工作站运行，但正式 CI 仍应补充标准测试结果格式、覆盖率和趋势报告。

### 当前一键测试数量和性质

| 测试程序集 | 当前数量 | 当前实际覆盖 | 不代表什么 |
|---|---:|---|---|
| Domain | 4 | 角度、失败语义、配方运动资格、有限运动值 | 不执行 HALCON |
| Application | 14 | 状态机、N点刚体拟合、T轴中心、ID对应、Reject/Fault、图像来源和运动门禁 | 不连接相机/PLC |
| Architecture | 3 | 分层依赖和 HALCON 类型隔离 | 不验证算法精度 |
| Runtime | 7 | 工位状态、ACK、Fault Reset、requestId幂等/冲突、残差DTO | 默认使用测试替身，不跑真实9201进程 |
| Infrastructure | 7 | 配方包哈希、篡改、路径穿越、激活索引 | 不证明生产数据库/磁盘耐久 |
| WPF | 17 | Shell构造、10个Feature、ROI、命令、教学/真实边界、离线运动保护 | 主要是STA/ViewModel自测，不是鼠标级UIA |
| **合计** | **52** | 当前默认软件自测 | 不包含下方Smoke/数据/HDevelop数量 |

另外三类证据单独计算：

- HALCON C# Smoke：真实加载 HALCON Runtime，执行正常、缺针、弯针等算法路径；
- Dataset：校验 manifest/SHA-256，并在 CMD 05 中经过 Runtime 9201 回归 3 个合成用例；
- HDevelop：使用 `hrun` 顺序执行 01～09，并检查每个程序的通过变量。

WPF 还提供一个**可选的真实 Runtime 集成测试**，它不在 CMD 01 的 52 项默认自测内。先启动 CMD 02，再执行：

```text
dotnet v2\tests\Vision.Engineering.Wpf.Tests\bin\Release\net9.0-windows\VisionSystem.Engineering.Wpf.Tests.dll --runtime-9201
```

它会额外验证生产页 Gateway 真实连接 `127.0.0.1:9201`、取得 Runtime 状态历史、完成 ACK，且保持
`EngineeringOnly / MotionAllowed=false`。

## 测试金字塔

下面每层列的是完整项目应达到的测试范围，不表示当前每一条都已经实现。当前证据和缺口必须同时看
[量产就绪矩阵](12-量产就绪矩阵.md)；没有自动化输出或实机报告的条目一律视为未完成。

### 1. Domain 单元测试

- 角度归一化；
- 坐标有限性和单位；
- 失败影响：Reject/Inhibit/Fault；
- 配方状态是否允许运动；
- 安全补偿范围和残差门限分离。

每次提交执行，不依赖 HALCON。

### 2. Application 单元测试

- 检测周期合法/非法状态迁移；
- N 点刚体拟合；
- T 轴非零中心公式；
- ID 缺失、重复和几何退化；
- 模拟针排禁止运动；
- 产品 NG 与系统 Fault 分离；
- 持久化失败、超时和互锁。

每次提交执行，不依赖 HALCON。

### 3. Architecture 测试

- Domain/Application 不引用 HalconDotNet、WPF、Socket 和 Infrastructure；
- WPF ViewModel 不暴露 HObject/HTuple；
- HALCON 类型不进入 Contracts；
- 项目依赖保持单向。

### 4. HALCON 组件测试

- 文件采集、灰度化、图像质量；
- Shape Model 加载/匹配/释放；
- ROI 跟随；
- 孔圆边缘/针尖轮廓拟合；
- 像素到机器坐标；
- 空图、错尺寸、模糊、过曝、遮挡和多个目标；
- 模型句柄循环加载与释放；
- 相同图像确定性和阶段耗时。

### 5. Dataset 回归

清单带图片 SHA-256、黄金标签和审核人。至少统计：

- OK 误杀、NG 漏检；
- FailureCode 混淆矩阵；
- 对真值的位置/角度偏差；
- 每针残差 P50/P95/Max；
- 耗时 P50/P95/P99；
- 候选配方相对 Active 的 A/B 变化。

关键缺针、弯针、严重错位集合在冻结验收集里不得出现错误放行 OK。

### 6. 协议和 Runtime 集成测试

- JSON 半包、粘包、非法字段和过长报文；
- requestId 幂等和冲突；
- Busy、ACK、Reset、非法状态；
- 客户端断线、服务重启、超时；
- 同一时刻只有一个相机/HALCON 周期；
- 结果 JSON、事件 JSONL 和响应一致；
- 磁盘不足、写入失败和模型损坏。

### 7. WPF 测试

当前 17 项已覆盖：

- 编译后的 WPF Shell 可构造，且由 10 个独立 Feature 组成；
- 每个 Feature 都提供为什么、输入输出、HALCON算子、单位、失败码和验收标准；
- ROI 支持 Rectangle1/Rectangle2/Circle/Polygon、坐标空间、定位跟随和 MVVM 命令；
- 项目 Gate、手动合成取像、ROI、模板教学、九点/T轴教学、配方 Gate、回归、追溯和维护命令可执行；
- 模板、标定、配方等教学动作明确声明不写 `.shm`/JSON/标定文件；
- Runtime 不可用时不会误报“算法已执行或结果已持久化”；
- 工程离线运动请求和配方激活始终被拒绝；
- WPF 程序集不直接引用 HalconDotNet。

仍待补充的 WPF 测试：

- ROI 坐标在缩放、平移、不同宽高比和 100%～200% DPI 下的自动互逆测试；
- Active 配方、用户角色和服务端权限的完整越权矩阵；
- 自动模式下禁止修改相机/ROI/模板/标定；
- FlaUI/UIA 鼠标级关键路径：ROI、模板、九点标定、回归、审批和激活；
- 长时间图像刷新、日志增长和窗口切换稳定性。

### 8. HIL 和耐久测试

- 相机硬触发、帧 ID、旧帧、丢帧、断线、曝光超时；
- 光源断线或亮度漂移；
- PLC 重复触发、结果超时、requestId 不一致；
- 急停、门禁、轴未停、Z 不安全；
- 磁盘满、许可证失效、进程重启；
- 8 小时调试、72 小时候选、168 小时发布稳定性；
- 预热后托管内存、HALCON 句柄、线程和文件句柄不持续单调增长。

## 0.05 mm 能力的建议分层门槛

下面是初始设计目标，不代表当前已达到；必须用真实硬件和误差预算确认。

| 项目 | 初始目标 | 当前离线能否证明 |
|---|---:|---|
| 物方采样 | ≤0.010～0.015 mm/px | 否，待 FOV/硬件 |
| 单相机独立平面验证最大误差 | ≤0.010～0.015 mm | 否 |
| 固定件 100～1000 帧定位 3σ | ≤0.008～0.010 mm | 合成图无意义 |
| PCB 孔中心对计量真值偏差 | ≤0.010 mm | 否 |
| 针尖中心对计量真值偏差 | ≤0.010 mm | 否 |
| T 中心 CW/CCW 端点误差 | ≤0.010 mm | 仅公式测试 |
| 补偿后预测最大单针残差 | 初始 ≤0.020～0.025 mm | 可验证软件计算 |
| 端到端实际径向最大误差 | ≤0.05 mm | 否 |
| GR&R | <公差的10%为目标 | 否 |
| Cmk/Cpk | 适用口径下 ≥1.67 | 否 |
| 严重 NG 错误放行 | 冻结集 0 例 | 合成集可测，真实集待建 |
| 节拍 | P99 不超过分配 | 可测离线算法，实机待测 |

## 重复性、准确度和分辨率不要混淆

- 分辨率：一个像素对应多少 mm；
- 重复性：同一物体不动，多次测量的离散；
- 准确度：平均测量与独立真值的偏差；
- 再现性：换人、换班、换装夹或换设备后的变化；
- 过程能力：长期分布相对规格的能力。

算法重复性很好但有 0.04 mm 固定偏差，仍不准确；像素当量 0.01 mm/px 也不代表总误差就是 0.01 mm。

## GR&R 建议设计

在安全量具/样件上至少覆盖多个代表工件、多个装夹/操作条件和多次重复。自动化设备“操作者”因素可替换为班次、装夹、相机热状态或设备。分析：

- 重复测量方差；
- 工件间方差；
- 装夹/班次/设备方差；
- 偏倚、线性和稳定性；
- 相对 0.05 mm 公差的百分比。

样本设计和结论应由质量/计量人员确认，不能由视觉开发独自签字。

## 发布门禁

候选版本只有同时满足才可发布：

- 代码和所有自动测试通过；
- 配方 schema、文件哈希、硬件指纹通过；
- 锁定数据集回归通过；
- 黄金图 dry-run 通过；
- 标定独立验证通过且未过期；
- HIL 故障注入和安全互锁通过；
- 性能/耐久通过；
- 质量审批完成；
- 回滚版本已验证。

发布不是复制一个 JSON，而是保存不可变证据包。
